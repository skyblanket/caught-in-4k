# Benchmark: frameread 0.1.0 vs mcp-video-analyzer 0.11.0 (2026-10-17)

> This benchmark was run when the project was called frameread. Same code, renamed to caught-in-4k.

Six public bug-report screen recordings from GitHub issues. Each tool ran with
default settings. For each video and tool, a separate Sonnet agent saw only
that tool's output (labelled A/B at random, tool names scrubbed, no issue
text, no web) and had to say what bug the recording reports. Answers were then
graded against the issue text: caught / partial / miss.

First pass only: neither the zoom tools nor the user's own description of the
bug were used, which makes this harder than real use.

| video | bug (issue) | frameread | mcp-video-analyzer |
|---|---|---|---|
| v1 [excalidraw#9662](https://github.com/excalidraw/excalidraw/issues/9662) | shape switch gives too-round corners | miss | miss |
| v2 [excalidraw#10948](https://github.com/excalidraw/excalidraw/issues/10948) | hit path offset from rotated curved arrow | partial | partial |
| v3 [excalidraw#9654](https://github.com/excalidraw/excalidraw/issues/9654) | flicker during alt-lasso | miss (1 frame) | miss |
| v4 [excalidraw#9710](https://github.com/excalidraw/excalidraw/issues/9710) | opacity bar broken in RTL | miss | miss |
| v5 [zed#40267](https://github.com/zed-industries/zed/issues/40267) | page scrolls when it shouldn't | partial | miss (1 frame) |
| v6 [vscode#339690](https://github.com/microsoft/vscode/issues/339690) | empty sessions appear in wrong group | miss (tiles too small) | caught (low confidence) |

Tokens per video (images at ~w*h/750 after resizing to 1568px, text at chars/4):

| | v1 | v2 | v3 | v4 | v5 | v6 | total |
|---|---|---|---|---|---|---|---|
| frameread | 3,446 | 3,095 | 785 | 2,835 | 3,146 | 3,118 | 16,425 |
| mcp-video-analyzer | 3,956 | 7,401 | 4,716 | 8,210 | 1,348 | 28,454 | 54,085 |

Notes:
- The competitor's scene detection found no cuts on 4 of 6 videos and fell back to uniform sampling.
- It ran on system ffmpeg 8 through a shim (its bundled binary download was blocked).
- No video had speech, so transcription played no part.

frameread weaknesses found:
- 512px tiles lose UI detail on Retina-size recordings (v6).
- Flicker never "settles", so only one frame was kept (v3).

## Round 2: after fixing those two (same videos, fresh blind judges, new A/B labels)

Fixes:
- A 60 fps flicker pass that adds flash frames as keyframes, marked FLICKER.
- A detail sheet of native-resolution crops around each changed region on screens 1600px or wider.

The competitor's output was unchanged but re-judged, to show judge variance.

| video | frameread R1 → R2 | mcp-video-analyzer R1 → R2 |
|---|---|---|
| v1 | miss → miss | miss → miss |
| v2 | partial → partial | partial → partial |
| v3 | miss → **caught** (flicker pass) | miss → miss |
| v4 | miss → **caught** (crops made the RTL slider and tab title readable) | miss → miss |
| v5 | partial → partial | miss → miss |
| v6 | miss → miss | caught → partial (same output, different judge) |
| caught / partial | 0/2 → **2/2** | 1/1 → 0/2 |
| tokens, 6 videos | 16,425 → 32,817 | 54,085 |

Caveats:
- The fixes were made on these same six videos, so round 2 flatters frameread.
- A held-out set is needed to confirm.
- The competitor's v6 result moved from caught to partial on identical input, so one-video differences are within judge noise.
- The detail sheet doubles frameread's token cost.
